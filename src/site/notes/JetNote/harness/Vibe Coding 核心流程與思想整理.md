# Vibe Coding 核心流程與思想整理

* 將開發過程中無序的思考,轉換成一套先有骨再有肉的流程
* 純化每個階段的職責,避免腦內打架造成的效率損失
* 同時因為啟動難度降低,因此可以提高動手率

---

## 1. 核心思想

* **先流程後實作**：先將業務流程拆解成可落地骨架（空 Function + 角色分工），降低同時處理流程與實作的認知負荷。
* **分層抽象漸進化**：在骨架階段先界定角色與責任，實作階段再依重複邏輯抽象功能。
* **骨架階段防護先行**：Try-Catch、簡單 Log 可骨架先放，保障流程可測通。
* **AI 協作優化**：AI 作為工具，用於生成骨架、模板、重複邏輯建議，而非替代思考。

---

## 2. 流程圖（縱向，帶循環思考）

```
[接任務]
    |
v
[理解需求]
    |
v
[流程拆解]
    |
v
[建立空 Function / Service 骨架]
    |
v
[初步串接流程]
    |
v
[逐步實作內容]
    |  
    v
<功能重複抽象 / 模組化> ---+
    |                      |
    +----------------------+
    v
[測試驗證]
    |
v
[回顧 / 知識回收] ---+
    |                  |
    +------------------+
    v
[下一輪開發 / 新任務]
```

### 說明

1. **接任務**：心理準備，確認需求長期維護或一次性功能。
2. **理解需求**：用流程圖 / 假code將邏輯釐清，標註不確定或異常情況。
3. **流程拆解**：拆成步驟，對每個步驟定義角色（Controller/Service/Repository/Utility）。
4. **建立空 Function / Service 骨架**：只定義方法簽名、回傳型別，內部先空，Try-Catch 可先放。
5. **初步串接流程**：把骨架串成完整流程，確保編譯與流程通順。
6. **逐步實作內容**：填充方法內容，邊寫邊測。
7. **功能重複抽象 / 模組化**：第二次或更多次出現的邏輯再抽象成共用方法或工具類，可循環回「逐步實作內容」。
8. **測試驗證**：小範例測資驗證每個 function 與流程，確保結果符合預期。
9. **回顧 / 知識回收**：記錄可複用方法、API、異常處理技巧，可循環回「下一輪開發 / 新任務」。

---

## 3. 針對性優化與補充

1. **Try-Catch & Log**：骨架階段先放簡單 Log，實作階段再細化例外分類與告警策略。
2. **AI Prompt 模板化**：對每個流程步驟可準備 prompt 模板，讓 AI 生成骨架或重複邏輯時符合既定結構。
3. **功能簽名與依賴注入**：空 Function 定義時，盡量透過 Interface / DI 設計，方便後續替換實作。
4. **回顧節奏固定化**：每完成一個功能模組，停 5 分鐘檢查：重複邏輯？流程可抽象？資料流可模板化？
5. **心理節奏**：先通、再穩、再美，避免一開始追求完美。心理負荷降低 → coding 心流更易達成。

---

## 4. Mindset 標語

* **流程先行，實作漸進**
* **骨架可跑，重複才抽**
* **AI 是助力，不是替代**
* **每次開發都是回顧與內化**
