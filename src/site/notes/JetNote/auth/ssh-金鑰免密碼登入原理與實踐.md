# SSH 金鑰免密碼登入原理與實踐

> **SSH（Secure Shell）** 在不安全網路中提供加密的遠端登入與資料傳輸。
> 相較於每次輸入密碼，實務上更推薦使用**非對稱金鑰（公私鑰對）**進行身分驗證。
>
> 本篇為 OS 層的認證筆記，與 [[JetNote/auth/內網 IoT 認證與加密筆記\|內網 IoT 認證與加密筆記]] 的應用層認證（TLS / JWT / API Key）互為對照。

## 一、公私鑰免密碼連線的底層邏輯

SSH 金鑰登入利用密碼學中的**非對稱加密**。

```
 [ Client 端：你的本機電腦 ]                         [ Server 端：遠端 Linux 伺服器 ]
┌─────────────────────────┐                        ┌──────────────────────────────┐
│  🔑 私鑰 (id_ed25519)   │                        │  📂 授權白名單檔案            │
│  (絕對保密、不可外傳)    │                        │  (~/.ssh/authorized_keys)    │
│                         │                        │  ┌────────────────────────┐  │
│  🛡️ 公鑰 (id_ed25519.pub)│ ─── (1) 一次性複製 ───► │  │ Client 端的公鑰內容...  │  │
└────────────┬────────────┘                        └───────────┬────────────┘  │
             │                                                 │              │
             │ ◄────────── (2) 挑戰：用公鑰加密訊息 ───────────┤              │
             │                                                 │              │
             │ ─────────── (3) 回應：用私鑰解密並簽章 ─────────►              │
             │                                                 │ (4) 驗證通過 │
             ▼                                                 ▼   允許登入   │
         [ 成功登入 ] ◄────────────────────────────────────────┘              │
                                                               └──────────────┘
```

### 1. 金鑰的角色分工

* **私鑰（Private Key）**：等同實體鑰匙。留在本機電腦（Client），**絕對不能給任何人、也不能在網路間傳遞**。
* **公鑰（Public Key）**：等同鎖頭／核准名單。可公開傳播，必須複製並登記在遠端伺服器（Server）的白名單中。

### 2. 挑戰與回應流程

1. **查榜單**：Client 向 Server 表示要金鑰登入，並出示公鑰標籤。
2. **出題（挑戰）**：Server 打開 `~/.ssh/authorized_keys`，確認有這把公鑰後，隨機產生一段字串（挑戰碼），用公鑰加密後傳回 Client。
3. **解題（回應）**：訊息是用公鑰加密的，全世界只有持有對應私鑰的 Client 解得開。Client 用私鑰解密後，進行數位簽章傳回 Server。
4. **放行**：Server 確認回傳內容無誤，證明連線者持有對應私鑰，同意免密碼登入。

## 二、金鑰生成指令

在 Windows 本機的 PowerShell 執行：

```powershell
ssh-keygen -t ed25519
```

* `ssh-keygen`：SSH 金鑰產生器，作業系統內建，用來隨機生成一對互相對應的公私鑰。
* `-t ed25519`：指定使用 **Ed25519** 演算法（愛德華曲線數位簽章演算法）。

### 為什麼不用傳統的 RSA 4096？

| 特性 | RSA 4096 | Ed25519（現代標準） |
|------|----------|---------------------|
| 金鑰大小 | 4096 bits（長長一整坨，運算較慢） | 256 bits（極小，只有一兩行，運算極快） |
| 安全性 | 高（數學原理較老舊） | 極高（現代橢圓曲線密碼學，無已知漏洞） |
| 相容性 | 完美（支援 20 年前的古董老設備） | 現代相容（近 10 年現代系統均完整支援） |

### 互動提示怎麼回答

1. `Enter file in which to save the key...` → 直接 Enter（用預設路徑）。
2. `Enter passphrase...` → 直接 Enter（不設密碼短語，才能真正免密碼自動登入）。
3. `Enter same passphrase again...` → 直接 Enter（再次確認不設密碼）。

## 三、實戰設定步驟（搭配 VS Code Remote-SSH）

VS Code Remote-SSH 的檔案總管只能看見本機 Windows 的空間，因此用以下流程把公鑰送過去。

### 步驟 1：在本機讀取並複製公鑰

```powershell
cat ~/.ssh/id_ed25519.pub
```

畫面會噴出一行以 `ssh-ed25519 AAAAC3...` 開頭的超長文字，請完整選取並複製整行。

### 步驟 2：貼入遠端白名單檔案

1. 透過 VS Code Remote-SSH 連線到遠端。
2. 選單 **檔案 (File) > 開啟檔案 (Open File)**。
3. 輸入遠端白名單路徑：`~/.ssh/authorized_keys`。
4. 貼上公鑰內容，**確保只有完整的一行、不要有奇怪斷行**，存檔（Ctrl + S）。

> 此檔可容納多支公鑰（一行一支）。筆電、桌電等不同裝置各自貼在不同行即可。

### 步驟 3：修正遠端安全權限（極重要）⚠️

`sshd` 對檔案權限要求極嚴格。若權限太開放（例如隔壁帳號也能讀寫），SSH 伺服器會**直接拒絕金鑰登入**。在遠端 Linux 終端機執行：

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```

* `700`：只有遠端帳號（擁有者）可讀寫執行 `~/.ssh`，其他人完全無法碰觸。
* `600`：只有遠端帳號可讀寫 `authorized_keys`。

## 四、維運與日常檢查指令

### 1. 本機金鑰自主檢查（Windows PowerShell）

```powershell
ls ~/.ssh
```

* `id_ed25519`：私鑰（**絕對不能外流**）。
* `id_ed25519.pub`：公鑰（用來貼到遠端）。

### 2. 遠端權限檢查（Linux Terminal）

若設定完仍被詢問密碼，檢查權限：

```bash
ls -ld ~/.ssh && ls -l ~/.ssh/authorized_keys
```

* 正確的資料夾權限開頭應為 `drwx------`。
* 正確的檔案權限開頭應為 `-rw-------`。

## 五、設計要點摘要

| 面向 | 作法 | 目的 |
|------|------|------|
| 金鑰演算法 | `ssh-keygen -t ed25519` | 金鑰短、運算快、現代曲線密碼學 |
| 公鑰登記 | 貼入 `~/.ssh/authorized_keys` | Server 建立可信任名單 |
| 目錄權限 | `chmod 700 ~/.ssh` | 僅擁有者可存取，避免 sshd 拒絕登入 |
| 檔案權限 | `chmod 600 ~/.ssh/authorized_keys` | 僅擁有者可讀寫 |
| 免互動登入 | passphrase 留空 | 自動化腳本／遠端連線不需輸入密碼 |
