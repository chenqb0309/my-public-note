## 什麼是互斥鎖（Mutex）？

- **互斥鎖（Mutex，Mutual Exclusion）** 是一種同步機制，主要用來**確保某個資源或程式在同一時間只能被一個執行緒或一個應用程式實例存取**。
- 它可以用來**防止程式被多開**，或者**確保多執行緒存取共享資源時不會發生衝突**。

### **比喻：互斥鎖 = 營業執照**

- 互斥鎖就像是一張**營業執照**，代表「這個應用程式可以運行」。
- **互斥鎖的控制者是 Windows（城管）**，Windows 會負責管理「執照的擁有者」，不允許兩個相同的執照同時存在。

**流程：**

1. **程式啟動時**，它會先向 Windows 申請一張營業執照（建立互斥鎖）。
2. **Windows 核發執照**，並幫程式保管，確保它是唯一的持有者。
3. **當第二個相同的程式實例啟動時**，它也會向 Windows 申請執照，但 Windows 會發現「這張執照已經有人持有」，因此拒絕它的請求，防止多開。

### **補充概念**

#### **1. 互斥鎖有作用範圍**

- **應用程式級（單機多開限制）**：常用來**限制同一台電腦上只能運行一個實例**，例如：
  ```csharp
  using System;
  using System.Threading;

  class Program
  {
      static void Main()
      {
          using (Mutex mutex = new Mutex(true, "Global\\MyUniqueMutex", out bool createdNew))
          {
              if (!createdNew)
              {
                  Console.WriteLine("程式已經運行，請勿重複開啟！");
                  return;
              }

              Console.WriteLine("程式執行中...");
              Console.ReadLine();
          }
      }
  }
  ```
  - `Global\\MyUniqueMutex`：互斥鎖的名稱，所有執行個體都會嘗試註冊相同的名稱。
  - `createdNew`：如果 `false`，代表互斥鎖已存在，程式已經運行。

#### **2. 互斥鎖可以跨程式或跨系統使用**

- **不同程式或跨機器同步**：可使用 `Global\\` 或 `Local\\` 命名空間來控制作用範圍。
- 例如 `Global\\MyMutex` 可以在整個系統範圍內生效，而 `Local\\MyMutex` 只限於當前使用者會話。

#### **3. `true` 與 `false` 的區別**

- **`new Mutex(true, "MyMutex")`**：
  - 代表**立即取得鎖**，若鎖已存在，則 `createdNew` 會是 `false`，可用於**防止程式多開**。
  - **適用於單例應用程式**，例如：防止開啟兩個相同的應用程式。

- **`new Mutex(false, "MyMutex")`**：
  - 允許程式啟動，但**不會馬上獲取鎖**，需要 `WaitOne()` 來請求鎖。
  - 適用於**控制「特定動作」是否需要鎖定**，例如：
    ```csharp
    using System;
    using System.Threading;

    class Program
    {
        static void Main()
        {
            using (Mutex mutex = new Mutex(false, "Global\\MyAppMutex"))
            {
                Console.WriteLine("程式啟動，請選擇模式:");
                Console.WriteLine("1. 檢視資料");
                Console.WriteLine("2. 修改資料");
                string input = Console.ReadLine();

                if (input == "2") // 只有當修改資料時才請求互斥鎖
                {
                    if (!mutex.WaitOne(0, false))
                    {
                        Console.WriteLine("已有另一個程式在修改資料，請稍後再試！");
                        return;
                    }
                    Console.WriteLine("已獲取鎖，執行修改...");
                    Console.ReadLine();
                    mutex.ReleaseMutex();
                }
                else
                {
                    Console.WriteLine("進入檢視模式，可多開...");
                    Console.ReadLine();
                }
            }
        }
    }
    ```
  - **檢視模式**（輸入 `1`）→ 允許多開，因為不會請求鎖。
  - **修改模式**（輸入 `2`）→ 嘗試獲取鎖，**如果已有其他程式在修改，就阻止新的修改動作**。

#### **4. 與其他同步機制的區別**

- **互斥鎖（Mutex）**：適用於**跨執行緒、跨應用程式**的互斥。
- **鎖（lock / Monitor）**：適用於**單個應用程式內的執行緒同步**，範圍較小，不能跨進程。
- **信號量（Semaphore）**：允許**部分共享**，不像互斥鎖那樣完全排他。

---

### **結論**

1. 互斥鎖不僅能防止多開，還能用來同步多執行緒對共享資源的存取。
2. 它的管理者是 Windows，程式向 Windows 註冊後，其他相同實例就會被攔截。
3. `Mutex(true, ...)` 用於防止整個應用程式多開，而 `Mutex(false, ...)` 可用來控制「某個操作」是否加鎖。
