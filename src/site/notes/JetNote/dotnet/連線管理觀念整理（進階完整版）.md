# 連線管理觀念整理（進階完整版）

## 1. 連線超時管理

* **連線建立超時**：在 connect 階段需要設定超時，避免無限等待。
* **傳輸過程超時**：即使連線建立成功，資料收發過程也需要超時控制，確保在伺服器無回應或異常延遲時能適時中斷。

## 2. 連線資源上限

* 系統可同時維持的連線數有限，受限於伺服器資源、作業系統 socket 限制、連線池大小。
* 超過上限會造成排隊、失敗或資源耗盡。

## 3. 連線池與資源管理

* 連線池可避免頻繁建立與銷毀連線。
* 必須考慮池大小、空閒回收、健康檢查。

## 4. Task 與非同步處理

* Task 適合處理等待與 IO，不會阻塞主執行緒。
* 必須協調 Task 數量與連線池上限，否則非同步變成排隊。

## 連線管理風險與解法對照表

| 主題              | 風險場景                                             | 常用解法                                               |
| --------------- | ------------------------------------------------ | -------------------------------------------------- |
| **連線超時管理**      | 缺少傳輸超時 → 請求長時間掛住，佔用資源，導致 thread/socket 被耗盡       | 設置 ReadTimeout / WriteTimeout，搭配 CancellationToken |
|                 | 沒有正確區分超時類型 → 只看到 timeout log，卻無法判斷是連線問題還是伺服器處理問題 | 在 log 中標記 timeout 類型（connect/read/write），並記錄耗時     |
| **連線資源上限**      | 無上限保護 → 高併發下，瞬間連線數爆炸，導致服務宕機                      | 設置連線上限與併發控制（SemaphoreSlim、限流器、排隊機制）                |
|                 | 連線池配置過大 → 記憶體與 context switch 成本增加，效能下降          | 壓測找出最佳池大小，根據 QPS 與硬體資源動態調整                         |
| **連線池與資源管理**    | 缺少健康檢查 → 拿到壞連線，不斷重試，產生雪崩效應                       | 在取出連線時實作驗證（ping / 簡單 query），確保連線有效                 |
|                 | 沒有 idle timeout → 閒置連線被切斷，應用端卻不自知                | 設定 IdleTimeout 與 KeepAlive，定期關閉或刷新連線               |
| **Task 與非同步處理** | Task 數量遠大於連線數 → 排隊時間過長，超時與重試同時爆發                 | 使用 SemaphoreSlim 控制並行度，讓任務數與連線池匹配                  |
|                 | 忽略取消機制 → 任務無法中斷，持續佔用資源                           | 所有 IO 任務都傳遞 CancellationToken，確保可中止                |

## Tips

* 超時要覆蓋整個連線生命週期
* 連線上限應預先規劃，而不是事後擴容
* 連線池必須有健康檢查與 idle timeout
* Task 與連線池要協調
* Timeout + Retry + 熔斷要搭配
* 觀測性必須明確

---

## 設計原則

* **容錯優於強連線**：連線一定會壞，系統應能優雅處理。
* **以資源上限規劃並行度**：Task 數量、併發量必須符合池大小與伺服器承載力。
* **超時、重試、熔斷三者搭配**：缺一不可。

---

## 測試與觀測方法

* **壓力測試**：模擬高併發，檢驗連線池大小與上限策略。
* **錯誤場景測試**：模擬高延遲、丟包、連線中斷，確認 timeout 與 retry 是否正常運作。
* **觀測指標**：

  * 平均與最大連線存活時間
  * 連線池命中率 / 拒絕率
  * 各類型 timeout 次數（connect / read / write）
